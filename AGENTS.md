# AGENTS.MD: WoW Forever Leveling System & Guide Repository

This repository hosts the 9-character Horde leveling, profession engine, and guide dashboard for *World of Warcraft: Forever*.

**Start every session by reading `FACTS.md` (checked game facts: trust only these for plan text) and `STATUS.md`** (current state, learned facts, open work, how the user likes to work). End every session by adding an entry to its Session Log.

## Repository Layout
- `personal/` (not in git): the user's team (`team.json`: names, races, professions, play order, bank), account and local character lists, `roster.js`, `history.sqlite`, backups. `scripts/team.py` `load_guide()` = `data/guide.json` + `personal/team.json` (else `personal.example/team.json`); every script reads the guide through it.
- `data/guide.json`: Source of truth for rosters, supply chains, zone routes, zone cards, and quest skips.
- `guide.md`, `data/guide.js`: Generated from `data/guide.json` by `make guide`. Do not edit by hand.
- `index.html`: Responsive second-screen web dashboard (Tailwind CSS). Page markup only; code lives in `js/` (plain scripts sharing globals, loaded in order: app, professions, characters, money, auction, recipes, camping, trainers, launch, route, ahpages, charmoney, legacy).
- `personal/roster.js` (your characters), `data/prices.js`, `data/trainers.js`, `data/vendors.js`: generated by `scripts/build_roster.py` from the addon save files and `personal/history.sqlite`. Every key carries the game client (e.g. `classic_beta|...`) so beta and live never mix.
- `data/zone_quests.js`: generated by `scripts/zone_quests.py` (Forever quest hubs per zone, levels 20+). Run it by hand when quest data changes.
- `scripts/refresh_data.py`: runs by itself on every Sync and `make guide`; rebuilds the QuestieDB-based files `data/dungeon_givers.json` (`scripts/dungeon_givers.py`, where each dungeon quest's giver stands) `data/vendor_items.json` (`scripts/vendor_items.py`, material vendors and trainers) `data/dungeon_levels.json` (`scripts/dungeon_levels.py`, monster levels per dungeon) `data/reagent_drops.json` (`scripts/reagent_drops.py`, monsters that drop Cooking / First Aid materials) and `data/rares.json` (`scripts/rares.py`, spawn, level and drops of the rares in guide.json `rares`). Add any new QuestieDB-built file here.
- `scripts/trainers_db.py`: writes guide.json `trainerDB` (Horde profession trainers from ClassicDB). No longer used by the plan (2026-10-24): trainers come from the game scans (`data/npcs.js`) and the Forever QuestieDB (`data/vendor_items.json` `trainers`). Facts checked in game live in `FACTS.md`.
- `addon/WoWForeverLeveler_ClassicTest/`: tiny addon for WoW Classic (`_classic_era_`) that shows the Planner's big alert (`Alert.lua`, copied from the Planner by `make addon`) on real game events; `/wfltest`. `make addon` installs only it into Classic folders, and never it into `_forever_`.
- `addon/WoWForeverLeveler_Quests/`, `addon/WoWForeverLeveler_Planner/`: the two window addons (old quest window; new overview window). They only pick tabs from the core's shared `WFL` table.
- `addon/WoWForeverLeveler/`: the core in-game addon (the user's main tool since 2026-10-13): `WoWForeverLeveler.lua` (data collection), `UI.lua` (window, menu, macros, tooltip), `Plan.lua` (generated by `make guide`). `make addon` installs it.
- `tests/addon_fakegame.py`: runs Plan.lua + UI.lua against a fake game (needs `lupa`, see its docstring). Run it after every UI.lua change.
- `tests/`: `make test` runs the dashboard math tests (Node) and the sync script tests (Python). Run it after every change.
- `GEMINI.md`: Core formatting constraints and evolution rules for AI assistants.
- `AGENTS.md`: Agent configuration, architectural context, and development guidelines.
- `scripts/`: Utility scripts (data loaders, official Battle.net API connectors, SavedVariables parser).

## Local Ports
- Dashboard: `./scripts/serve.sh` serves `index.html` on `http://localhost:8765/`.
- Port `8000` is reserved for the Battle.net OAuth callback in `scripts/sync_characters.py`. Do not serve the dashboard on it.

## System Rules & Constraints
1. **Master Roster Structure (9 Characters, groups set in `personal/team.json`):**
   - Since 2026-10-24: **Group 1** (played first, covers all 9 professions): Tauren Hunter, Orc Warlock, Undead Priest, Troll Shaman, Orc Warrior. **Group 2:** Undead Rogue, Undead Paladin, Undead Mage, Tauren Druid. Group 3 is empty (empty groups are skipped).
   - Dungeon levelers: `"dungeons": true` and `"spec"` per character in `personal/team.json` (Protection Warrior, Holy Priest). They take no gathering profession; the Next tab shows the quest gaps between dungeon chains (`guide.json` `dungeonGaps`).
   - Professions are flexible: each character's planned `profs` live in `data/guide.json` and can be changed from the dashboard picker. Real professions from the addon override the plan on the dashboard.
   - Supply chains are derived, never hand-written: gatherers send to crafters listed in each gather profession's `usedBy`, same group first. Crafted goods flow the same way through `professions.<code>.crafts` (`to: "all"`, a list of profession codes, or `toClasses`). Pair tips live in `synergies`; green items per skill step in `milestones[].greens`. The logic exists twice and must stay in sync: `supply_lines()` in `scripts/build_guide.py` and `supplyLines()` in `js/professions.js`.
   - Battle.net's Classic profile API has no professions endpoint (tested: 404), so professions come only from the addon.
2. **Profession Abbreviations:** Always use: `skin`, `herb`, `mine`, `tail`, `ench`, `leath`, `eng`, `bsmith`, `alch`.
3. **Data Integrity & Compliance:**
   - Strictly adhere to Blizzard Entertainment Terms of Service and API policies.
   - Do NOT scrape Battle.net directly.
   - Use official Battle.net Developer Portal APIs (`develop.battle.net`) with OAuth 2.0 or parse local in-game `SavedVariables` generated by compliant Blizzard Lua addons.
4. **Markdown Formatting:**
   - Keep tables readable with `<br>` tags rather than excessive horizontal sprawl.
   - Maintain skip lists categorized strictly by zone.
